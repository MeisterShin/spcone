# 좌석배치 인라인 편집 모드 + 모바일 자리 이동 설계

## 배경
사용자 피드백(그대로 인용): "좌석배치도에서 좌석규모와 복도 위치 수정이 안 된다."

조사 결과, 기능 자체는 동작하고 있었음(좌석 규모는 "행사 관리 → 편집" 모달에서, 복도는 좌석배치 화면의 행/열 헤더 숫자 클릭으로 변경 가능하며 둘 다 저장·새로고침 후에도 유지됨을 라이브 사이트에서 확인). 그러나 사용자 확인 결과 실제 문제는 다음 두 가지였다:
1. 좌석배치 화면 "안에서 직접" 수정하고 싶은데, 그 화면에 수정 가능해 보이는 버튼/신호가 전혀 없었다(복도 헤더는 그냥 평범한 숫자로 보여서 클릭 가능한 컨트롤로 인지되지 않음, 규모는 아예 다른 화면에서만 바꿀 수 있어 이 화면만 봐서는 방법을 알 수 없음).
2. 모바일에서는 자리 간 이동(교체)이 거의 동작하지 않는다 — 기존 구현이 HTML5 `draggable`/드래그 이벤트 기반인데, 이는 터치 디바이스에서 기본적으로 지원되지 않는 알려진 제약.

## 확정된 방향 (사용자 승인)
- 자리 이동: 데스크톱은 기존 드래그 그대로 유지, 모바일(터치 기기)에만 탭 기반 방식을 별도로 추가.
- 인라인 편집 UI: "편집" 토글 버튼 → 켜면 화면 상단에 가로/세로 칸수 입력란이 나타나고, 동시에 복도 헤더가 눈에 띄게 "클릭 가능" 스타일로 바뀜(꺼져 있으면 정적인 숫자로만 보임).

## 1. 좌석배치 화면 인라인 편집 모드

### 상태
새 페이지 상태 `SEAT_EDIT_MODE`(boolean, 기본 false). 다른 화면 상태(`CI_FILTER` 등)와 동일한 패턴의 모듈 전역 변수 — 페이지를 벗어나거나 새로고침하면 자동으로 꺼진 상태로 리셋(별도 영속화 없음).

### UI
- `seating.edit` 권한이 있을 때만 "추천배치 적용" 버튼 왼쪽에 "편집"/"편집 종료" 토글 버튼 노출(기존 현장 체크인의 "오프라인 시연" 버튼과 동일한 온/오프 스타일 재사용).
- `SEAT_EDIT_MODE`가 켜지면 그리드 위에 "가로 칸수"/"세로 칸수" 숫자 입력란(현재 `ev.seatConfig.cols`/`rows` 값으로 채움) + "적용" 버튼이 나타남.
  - "적용" 클릭 시: 두 값을 1~40 범위로 clamp(기존 `saveEvent`의 규칙과 동일), `ev.seatConfig`에 반영(복도 배열 `aisleRows`/`aisleCols`는 그대로 보존 — 좌표 자체가 범위를 벗어나게 되는 경우에도 배열 값은 건드리지 않음, 화면에는 그 칸이 더 이상 없으니 자연히 반영 안 됨과 동일한 기존 규칙), `save(['events'])`, `audit('event', ev.id, 'seat_resize', ...)`, 재렌더.
  - 이미 배치된 내빈의 `seat{row,col}` 좌표는 건드리지 않는다(칸수를 줄여 좌표가 그리드 밖으로 나가도 데이터는 삭제하지 않음 — CLAUDE.md 규칙 2 "삭제 대신 상태 변경" 원칙과 동일 선상. 화면에는 그 내빈이 보이지 않게 되며, 담당자가 "추천배치 적용" 또는 수동 이동으로 재배치하면 됨).
- `SEAT_EDIT_MODE`가 켜져 있을 때만 행/열 헤더 버튼이 실제로 클릭 가능(현재는 `seating.edit` 권한만 있으면 항상 클릭 가능 → 이제는 권한 + 편집모드 둘 다 필요)하고, 배경색·호버 강조 등으로 "지금은 클릭하면 복도가 토글됩니다"를 시각적으로 알린다. 편집모드가 꺼져 있으면 헤더는 disabled 상태의 정적 숫자로 보인다(현재 조회 전용 사용자에게 보이는 것과 동일하게).
- 좌석 간 이동(교체)은 이 편집모드와 무관하게 지금처럼 항상 가능 — 별도 개념이므로 토글의 영향을 받지 않는다.

## 2. 모바일 자리 이동 (탭 방식)

### 기기 감지
`const IS_TOUCH = matchMedia('(pointer: coarse)').matches;` — 페이지 로드 시 1회 계산해 상수로 보관(리사이즈 도중 기기 성격이 바뀌는 경우는 고려하지 않음, 데모 앱 스코프).

### 상호작용
- **터치 기기(`IS_TOUCH===true`)**: 좌석 칸을 탭하면 선택되어 하이라이트 표시(`seat-selected` 클래스). 이 상태에서 다른 칸을 탭하면:
  - 그 칸에 다른 내빈이 있으면 → 두 자리를 맞교체(`swapSeats` 재사용).
  - 그 칸이 빈 자리면 → 선택된 내빈을 그 자리로 이동(`moveSeatTo` 재사용).
  - 선택된 자리와 같은 칸을 다시 탭하면 → 선택 취소(아무 동작 없음).
  - 복도 칸을 탭하면 → 아무 동작 없음(선택 상태 유지, 잘못 탭해도 선택이 풀리지 않아 다시 정확한 자리를 탭할 수 있음).
  - 이동/교체가 완료되면 선택 상태는 자동 해제.
  - 화면에 "자리를 탭해 선택한 뒤, 이동할 자리를 다시 탭하세요" 안내 문구를 그리드 위에 작게 표시(터치 기기에서만).
- **비터치 기기(`IS_TOUCH===false`)**: 기존 HTML5 드래그 앤 드롭(`initSeatDnD`) 그대로, 변경 없음.
- 두 경로는 기기 감지로 완전히 분리되어 있어 서로 영향을 주지 않는다.

### 테스트 가능 구조
탭 두 번의 결과를 "무엇을 할지 결정하는" 부분을 순수 함수 `seatTapAction(selectedEgId, tappedEgId, tappedRow, tappedCol)`로 분리:
- `selectedEgId===null` → `{action:'select', egId:tappedEgId}` (탭한 칸이 비어있으면 `tappedEgId`가 없으므로 `{action:'none'}`)
- `selectedEgId!==null && tappedEgId===selectedEgId` → `{action:'deselect'}`
- `selectedEgId!==null && tappedEgId` (다른 내빈) → `{action:'swap', a:selectedEgId, b:tappedEgId}`
- `selectedEgId!==null && !tappedEgId && tappedRow!=null` (빈 자리) → `{action:'move', egId:selectedEgId, row:tappedRow, col:tappedCol}`
- 복도 칸(row/col 정보 없음) 탭 → `{action:'none'}`

이 함수는 DOM/터치 이벤트와 무관한 순수 로직이라 Node 테스트 하니스로 전 분기 자동테스트 가능. 실제 터치 이벤트 리스너 연결(`initSeatDnD`가 `IS_TOUCH`에 따라 클릭 리스너를 대신 붙이는 부분)과 `matchMedia` 자체는 브라우저 전용이라 자동테스트 대상이 아니며, 육안 확인으로 대체(사진 업로드 리사이즈 로직과 동일한 전례).

## 에러 처리
- 편집모드에서 칸수 입력값이 비어있거나 숫자가 아니면 기존 `saveEvent`와 동일하게 기본값(10/8)으로 대체 후 clamp — 별도 에러 다이얼로그 없음.
- 탭 방식에서 잘못된 탭(복도, 같은 자리 재탭)은 조용히 무시/선택취소 — 에러 토스트 없음.

## 테스트
- 좌석 규모 인라인 적용: 편집모드에서 칸수 변경 → `ev.seatConfig` 갱신, 복도 배열 보존 확인.
- 편집모드 on/off에 따른 복도 헤더 클릭 가능 여부(렌더된 `disabled` 속성 유무로 확인).
- `seatTapAction` 순수 함수의 5가지 분기(select/deselect/swap/move/none) 전부.
- 회귀: `IS_TOUCH===false`일 때 기존 드래그 관련 렌더/동작 변경 없음, 편집모드 도입 후에도 좌석 이동 자체는 항상 가능함을 확인.

## 범위 밖
- 편집모드 상태 영속화(새로고침하면 항상 꺼진 채로 시작).
- 터치 기기에서 드래그 방식 병행 지원(탭 방식만 제공).
- 좌석 규모를 줄여서 그리드 밖으로 밀려난 내빈을 자동으로 재배치하는 기능(수동 재배치 또는 "추천배치 적용"으로 해결하는 기존 흐름 그대로).
